🧭 Prompting & Steering
Four independent mechanisms change how a prompt is processed — combine any of them.
"override" keywordIn-prompt text — bypasses .gitignore during context gathering
Typing the literal word override (or all files, gitignored, ignored) anywhere in your prompt makes the workspace context gatherer scan every file, including .gitignored ones — useful for inspecting build output, node_modules config, or .env templates. It only changes which files are visible to context-gathering; it does not affect model choice, persona, or task type.
"Check the override — read all files under dist/ for the compiled output"
Task-lane DSL prefixesIn-prompt text — forces sequential vs. parallel subtask order
Prefix individual lines in a multi-step prompt to override the automatic planner's heuristics:
  • > — run in parallel (auto-downgraded to sequential if two parallel tasks share the same classified task type)
  • -, *, or 1. — run sequentially
> read auth.ts > search for API keys - implement new middleware
Persona auto-detectionIn-prompt phrasing — changes context ranking and response style
The server classifies every prompt into a persona by scanning its text for phrase patterns, first match wins, checked in this order:
PersonaTriggered by phrases like...
debuggererror, exception, bug, crash, stack trace, leak, broken, "why does", type error, undefined, null, failed, issue, schema, variable, parameter
researcherpdf://, paper, citation, arxiv, research, study, thesis, literature
student"explain how", "how to", tutorial, "what is", learn, teaching, concept
marketerseo, marketing, campaign, keyword, traffic, ad
plannerplan, roadmap, timeline, milestone, phase, step
coderimplement, refactor, class, function, method, interface, module, compile, run, build, test, package.json, tsconfig.json
genericfallback — none of the above matched
Pin a persona explicitly (always wins over heuristics) by adding this line to your workspace's .agents/AGENTS.md (canonical location — auto-created there, walks up to a monorepo root if nested; falls back to a legacy root-level AGENTS.md if that's all that exists):
preferred persona: coder
keywords parameterAPI param on use_free_llm — steers doc-section selection, not persona
keywords is a string[] field passed on the tool call itself (not typed in the prompt). It boosts which sections of injected reference documentation get prioritized when the system prompt is assembled. It has no effect on persona or task-lane routing — those are driven entirely by the prompt text mechanisms above.
